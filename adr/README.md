# ADR 목록

핵심 설계 결정의 기록이다. 각 문서는 **맥락 / 고려한 대안 / 선택과 근거 / 버린 이유와 trade-off** 순서로 적었다. 전체 설계는 [DESIGN.md](../DESIGN.md)에 있다.

| # | 결정 | 구현 여부 |
|---|---|---|
| [0001](0001-most-dangerous-point.md) | 구현으로 증명할 가장 위험한 지점은 "두 DB에 걸친 쓰기의 부분 반영"이다 | 구현 |
| [0002](0002-database-split.md) | 주문·결제·장바구니는 신규 DB, 재고·포인트·쿠폰은 레거시 DB에 둔다 | 구현 (주문) |
| [0003](0003-cross-database-write.md) | 두 DB를 한 트랜잭션으로 묶지 않고, 의도 기록 + 레거시 반영 기록 + 복구로 수렴시킨다 | 구현 |
| [0004](0004-stock-conditional-update.md) | 재고 차감은 조건부 UPDATE로 한다 | 구현 |
| [0005](0005-payment-partial-failure.md) | 복합 결제에서 일부 수단이 실패하면 전체를 취소한다 | 설계만 |

결정들의 관계:

- 0002가 DB 경계를 정하고, 그 경계에서 생기는 문제를 0003이 푼다.
- 0003의 레거시 쪽 트랜잭션 안에서 0004의 방식으로 재고를 차감한다.
- 0005의 외부 결제가 실패하면 0003의 반환 절차로 레거시 자원을 되돌린다.
- 0001은 이 중 무엇을 코드로 증명할지를 정한다.
